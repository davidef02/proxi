# Agent lessons

- L11 [1×, last 2026-11-12, #2] When porting a settings key or any key whitelist between Node and Rust: cover it in every path (`validate`, read/`apply`, write and the parity test) from one canonical key list (a key present in `SETTING_KEYS` but missing from `validate` was dropped on GET and erased by the next POST).
- L12 [2×, last 2026-11-13, #3] When writing test fixtures that look like real secrets (`sk`-style keys): build them at runtime from low-entropy pieces (e.g. `common::fake_key`, `"harness".repeat(3)`) instead of committing literals (`scripts/preflight-secrets.mjs` scans tracked files and the CI gitleaks job scans commits, so a high-entropy join still turns CI red).
- L13 [2×, last 2026-11-13, #3] When prose (a doc, a comment, a lesson) must name a secret-like prefix: write it so the preflight scanner cannot match it (e.g. `sk`-style), because the scan covers every tracked file and a single lesson line turned `checks` red on HEAD.
- L15 [1×, last 2026-11-12, #1] When spawning a child process on Windows with `execFile`/`spawn` (especially `shell: true`): run `.exe` files without the shell, or quote the binary and its arguments (an unquoted `C:\Program Files\nodejs\node.exe` is split by cmd.exe, so `desktop:smoke` hung on a native dialog and cost a fix round).
- L16 [1×, last 2026-11-13, #3] When capturing a golden/parity fixture that another implementation replays: keep the input seed raw and normalise only the captured outputs (a normalised seed makes the replay exercise different input and hides the parity bugs the fixture exists to catch).
- L17 [1×, last 2026-11-14, #6] When capturing a Node CLI's output into a golden replayed on another OS: pin only the platform-neutral part of OS-dependent text (e.g. the ENOENT prefix) and assert the per-platform tail in a `cfg!`-gated test (Node prints the resolved path on Windows but the argument as typed on POSIX, so a Windows capture turns the Linux CI red).
- L18 [1×, last 2026-11-14, #6] When reading a fixed byte range of a path or other string (`&path[1..2]` for a drive letter): check `as_bytes().get(n)` or a char boundary first (a multibyte character panics and the CLI dies instead of writing the lesson).
- L19 [1×, last 2026-11-14, #6] When a test fixture needs an absolute path: use a neutral root like `C:/data/...`, never a real user-home path (`tests/repo-meta.test.ts` and `scripts/preflight-secrets.mjs` scan every tracked file for personal paths).
- L21 [1×, last 2026-11-14, #4] When building JSON in Rust that must match Node's key order under `serde_json/preserve_order`: build a fresh `Map` inserted in the Node order and assert the serialised string, never `remove` or append into an existing one (`Map::remove` is `swap_remove` and `insert` appends, so `inProgress` came first and `title` last).
- L22 [1×, last 2026-11-14, #4] When hand-porting a JS regex or scan to Rust: mirror the reference traversal exactly (one alternation pass with the earliest match winning, retry at `start + 1`, a stripped line keeps its newline) and test the exact Node output (two-pass stripping, dropped newlines and a `start + 3` skip each diverged and cost a fix round).
- L23 [1×, last 2026-11-13, #8] When several Rust integration-test binaries need the same seed or golden helpers: define them once in `crates/proxi/tests/common/` and call them from each test file (per-binary copies drift silently, so editing one leaves the others untested and review sends the change back).
- L24 [1×, last 2026-11-13, #9] When bounding a blocking pass in Tokio: stop it cooperatively or shut the runtime down with `shutdown_timeout`/`shutdown_background` (`timeout` around `spawn_blocking` leaves the task running and dropping the runtime waits for it, so quitting hangs for minutes).
- L20 [1×, last 2026-11-13, #9] When a request handler writes shared state after an await: re-check the cancel token or epoch under the same lock as the canceller before writing (a cancel that lands during the await otherwise leaves stale pending state forever).
- L21 [1×, last 2026-11-14, #13] When porting a JS `for...of` over a JSON value to Rust: treat a string as iterable of one-character values and keep the throw for numbers, booleans, objects and null, with a success and a failure test per shape (Node returned 0 cards for a string `nodes` where Rust threw `not iterable`, so the failure boundary diverged and cost a fix round).
- L22 [1×, last 2026-11-14, #13] When an output line or a minted file path must match Node's `path.join`: build it with the lexical join helper (`crate::lesson::node_path::join`) and assert the exact printed path, never `Path::join`/`PathBuf::push` (`Path::join` keeps `./` and `..`, so `--base-dir ./out` printed `./out/decks/...` where Node printed `out/decks/...`).
- L25 [1×, last 2026-11-14, #12] When porting Node code into a new Rust module and the crate already has the same helper (e.g. `esc`): make the existing one `pub(crate)` and call it, never copy the function (a byte-identical copy in `reference.rs` would drift from `doc::esc`, and review sent it back).
