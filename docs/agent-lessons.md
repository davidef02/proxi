- L1 [1×, last 2026-11-04, #44] When putting text on a translucent accent surface (`bg-<token>/20`): check the composited pair against the AA 4.5:1 that `app/test/theme-tokens.test.ts` enforces, in every palette and both modes, before finishing (that test pins solid token pairs only, so a 20 % tint silently drops 10 px warn text to 4.33:1).
- L2 [1×, last 2026-11-05, #46] When importing or syncing external service data (like Anki) on page load or window focus: fetch primary page data concurrently without awaiting the sync, refetching only if imported count > 0 (awaiting slow or offline external bridge endpoints delays initial render and stalls the UI on window focus).
- L3 [1×, last 2026-11-05, #47] When extracting a helper so an imperative renderer (canvas, DOM painting) can be unit-tested: build the drawn output from that helper (e.g. key the cached paths by its return value) instead of re-implementing its mapping by hand in the draw code (a tested copy the frame never calls cannot guard what is drawn, and review sends it back).
- L4 [1×, last 2026-11-05, #47] When editing an existing file for a task: leave unrelated lines (section banners, comments, formatting) byte-identical to the base branch and keep the diff to the task's change (a shortened banner alone cost a full fix round).
- L5 [1×, last 2026-11-06, #49] When adding a rule or line to a prompt builder (or any function with several early returns): emit it on every return path, including the "input present but nothing matched" one, and test that path (review sent back a prompt with the new `Opening:` rule missing from the not-found-with-picks branch).
- L6 [1×, last 2026-11-06, #65] When changing how a lookup or match behaves (e.g. whole-phrase to partial fallback): update in the same change every prompt sentence that describes the old behaviour (a prompt that contradicts the code makes the model follow the wrong rule, and review sends it back).
- L7 [1×, last 2026-11-06, #65] When checking that prose names a stored concept: compare against the canonical value looked up by id, and fall back to the model-supplied name only when the record is deleted (validating the model's own echo lets a wrong name pass silently).
- L8 [1×, last 2026-11-06, #65] When comparing free prose with stored names: normalise both sides through one shared helper that trims and strips markup/emphasis, and measure length on the trimmed value (one-sided or whitespace-blind normalisation yields false mismatches).
- L9 [1×, last 2026-11-06, #65] When a behaviour depends on prompt wording: verify it with a real eval run (`npm run eval -- <scenario>`), not only assertions on the prompt text (two rounds of #65 were green on prompt tests while the real session still ignored the prompt).
- L10 [1×, last 2026-11-10, #71] When a repo-wide grep test asserts that no tracked file references a path or pattern: exclude the file that declares the ignore rules (`.gitignore`) with a pathspec such as `:!.gitignore` (ignore rules match the pattern but are not references, so the test goes red on its own config).
- L11 [1×, last 2026-11-12, #2] When porting a settings key or any key whitelist between Node and Rust: cover it in every path (`validate`, read/`apply`, write and the parity test) from one canonical key list (a key present in `SETTING_KEYS` but missing from `validate` was dropped on GET and erased by the next POST).
