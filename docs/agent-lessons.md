# Agent lessons

- L12 [2×, last 2026-11-13, #3] When writing test fixtures that look like real secrets (`sk`-style keys): build them at runtime from low-entropy pieces (e.g. `common::fake_key`, `"harness".repeat(3)`) instead of committing literals (`scripts/preflight-secrets.mjs` scans tracked files and the CI gitleaks job scans commits, so a high-entropy join still turns CI red).
- L13 [2×, last 2026-11-13, #3] When prose (a doc, a comment, a lesson) must name a secret-like prefix: write it so the preflight scanner cannot match it (e.g. `sk`-style), because the scan covers every tracked file and a single lesson line turned `checks` red on HEAD.
- L22 [1×, last 2026-11-15, #15] When spawning a `.cmd`/`.bat` shim from Rust on Windows: pass the shim path as the program and let `std::process::Command` escape its arguments (since Rust 1.77.2 it runs batch files without `cmd.exe`, whose re-parse splits `C:\R&D\dati` on `&`).
- L38 [1×, last 2026-11-15, #15] When deleting a TS test file after porting it to Rust: check every case against the port and keep the ones with no Rust home (the `retry()` and `action-denied` cases were deleted un-ported and review sent it back).
- L39 [1×, last 2026-11-15, #15] When a test needs Node or another external prerequisite: make its helper panic like `common::require_node()` instead of printing "skipping" and returning false (the golden test went green without checking anything).
- L23 [1×, last 2026-11-14, #14] When rejecting a request by `content-length` before reading its body: drain the body before answering the error (an unread body resets the connection and the client sees `ECONNRESET`).
- L24 [1×, last 2026-11-14, #14] When adding a body validator in `server.rs`: parse through the shared `body_object`/`required_string` helpers and reuse `COURSE_PATTERN` instead of re-implementing the type match or repeating the literal (duplicated validation drifts and review sends the change back).
- L33 [1×, last 2026-11-14, #13] When porting a JS `for...of` over a JSON value to Rust: treat a string as iterable of one-character values and keep the throw for numbers, booleans, objects and null, with a success and a failure test per shape (Node returned 0 cards for a string `nodes` where Rust threw `not iterable`, so the failure boundary diverged and cost a fix round).
- L26 [1×, last 2026-11-14, #13] When an output line or a minted file path must match Node's `path.join`: build it with the lexical join helper (`crate::lesson::node_path::join`) and assert the exact printed path, never `Path::join`/`PathBuf::push` (`Path::join` keeps `./` and `..`, so `--base-dir ./out` printed `./out/decks/...` where Node printed `out/decks/...`).
- L34 [1×, last 2026-11-15, #20] When a Rust port must reproduce a default of Node's request parsing (mime type, part name): read it off Node's own server and keep one test that runs against both (a Rust-only test only encodes the guess, and WHATWG `formData` gives a part with no `Content-Type` `text/plain`, not `application/octet-stream`).
- L35 [1×, last 2026-11-15, #20] When matching a Node `path` function in Rust: pin the Node output on edge inputs before writing the port (`path.win32.basename("C:foo.png")` is `"foo.png"`: it drops the drive designator, so a split on separators returned the whole name).
- L36 [1×, last 2026-11-15, #20] When a test kills or restarts the server after a state change: wait for the debounced on-disk flush (`state.json`) before closing (`sessions.rs` flushes it 300 ms late, so a restart inside that window loaded a stale `running` turn).
- L37 [1×, last 2026-11-15, #20] When production code must arm a timer or spawn a process: cover the arming through the caller, not only the handler it calls (`turns.rs` tests called `watchdog_fired` directly, so deleting `spawn_delayed(WATCHDOG, …)` from `SessionManager::interrupt` left every test green).
- L31 [1×, last 2026-11-15, #24] When reading a Windows child process's stdout from `powershell` (Windows PowerShell 5.1): prefix the script with `[Console]::OutputEncoding=[Text.Encoding]::UTF8` and refuse to write the value back if it still contains U+FFFD (PS 5.1 encodes stdout in the OEM code page, so a non-ASCII `Path` entry was decoded as UTF-8, came back as U+FFFD and would have been written back, corrupting unrelated PATH entries).
- L40 [1×, last 2026-11-15, #23] When building a spawned process's startup error from its stderr: settle on `close`, not `exit`, and drop any delay a test added to make the message appear (Node emits `exit` before the last stdio chunks arrive, so a binary that dies at startup loses the diagnostic that explains why).
