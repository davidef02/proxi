# PLAN 7 — `proxi home generate|plan|chapters|help` in Rust

## Goal

Port the `home` CLI (`extensions/homepage.ts` + `extensions/chapter.ts` + `extensions/slug.ts` + the
AnkiConnect calls of `extensions/anki-client.ts`) to the Rust binary so that `proxi home <args>` prints the
same stdout/stderr, exits with the same code and writes the same files as
`node --import tsx extensions/homepage.ts <args>` (= `npm run home -- <args>`), with Node outputs committed as a
golden fixture (A12) that the Rust tests replay without Node. The TypeScript modules stay untouched (the server
and the `lesson` CLIs still use them); only their unit tests move to Rust (D10).

## Acceptance criteria

- AC1 `proxi home generate --no-anki` (also bare `--no-anki`, with `--dir/--curriculum/--out`, and on an empty
  data root) writes an `index.html` byte-identical to Node's, prints the same stdout/stderr and exit code
  (golden cases `generate-no-anki`, `generate-default-command`, `generate-options`, `generate-empty`).
- AC2 `proxi home generate --anki-url <fake AnkiConnect>` writes the same homepage as Node once the
  `Dati Anki al <dd/mm/yyyy, HH:MM:SS>` stamp is normalised; the raw Rust stamp matches that it-IT pattern; the
  AnkiConnect request bodies equal Node's (golden case `generate-anki`, clock unit tests).
- AC3 `proxi home plan ...` writes the same `curriculum.json` bytes as Node (new chapter, re-planned chapter
  keeping other chapters' unknown keys) and prints the same line; its error cases print the same `Error: ...`
  and exit 1 without writing (golden cases `plan-*`).
- AC4 `proxi home chapters` prints the same listing as Node and leaves every file in the data root unchanged
  (golden cases `chapters`, `chapters-options`, `chapters-empty`, `chapters-malformed`: `files` is `{}`).
- AC5 With AnkiConnect unreachable (closed port) or answering an error, `generate` prints the same
  `Error: AnkiConnect non raggiungibile (...)...` line, exits 1 and writes no file, exactly as Node (golden cases
  `generate-anki-unreachable`, `generate-anki-error`).
- AC6 `cargo test --locked` passes and contains the Rust tests that replace the curriculum, scan, join/render,
  generation and `fetchAnkiStatus` groups of `tests/homepage.test.ts`; that TS file keeps only the
  `fetchDeckStatus` group (server-only, issue #8).

## Design

**Approach.** One Rust module per TS module, same function boundaries, so each can be diffed against its
source: `slug.rs` (slug.ts), `chapter.rs` (chapter.ts), `anki.rs` (anki-client.ts `invoke` + homepage.ts
`fetchAnkiStatus`), `homepage.rs` (homepage.ts library half + `escapeHtml`/`parseLessonDocument` from
html-lesson.ts), `home.rs` (homepage.ts `runCli` + `parseArgs` replica), plus two leaves: `identity.rs`
(`APP_NAME`, `DECK_ROOT`) and `clock.rs` (ISO and it-IT local time). `main.rs` routes `home` before clap, like
`data` (D11: Node's help/usage and `parseArgs` messages, not clap's).

**Parity strategy (A2, A12, A7).** A new capture `app/test/capture-golden-home.ts`, called from
`captureGolden`, runs the real Node CLI in a child process for each scripted case on a fresh temp data root
(seeded from raw file contents, L16), with a scripted fake AnkiConnect (Node `http` server) or a closed port,
and writes `crates/proxi/tests/fixtures/golden/home.json`. One JSON file (not a directory of raw files) because
`capture-golden.test.ts` compares parsed JSON, which is immune to `core.autocrlf` rewriting the checkout; HTML
and curriculum bytes live inside JSON strings, so `\n` stays `\n`. `crates/proxi/tests/home_golden.rs` replays
every case against the spawned binary (process-global `chdir`, so never in-process) with a Rust fake
AnkiConnect (std `TcpListener`, in `tests/common/mod.rs`), applies the same normaliser and asserts equality.
Normalisation, identical on both sides, only touches captured outputs: data-root path variants →
`<dataRoot>`, then `\` → `/` in stdout/stderr (Windows capture vs Linux CI); the text after
`Malformed #lesson-data island: ` → `<json-error>` (V8 `JSON.parse` messages are not reproducible); in file
contents `Dati Anki al dd/mm/yyyy, HH:MM:SS` → `Dati Anki al <it-IT>` (A2 Research: homepage Anki stamp).

**Key decisions.**
- `home` does **not** read `LEARNER_ANKI_URL`: the Node `home` CLI only wires `--anki-url`
  (`homepage.ts:186, 640`), and D11 requires identical flags/behaviour. The Key interface stays the server's
  (`app/server/main.ts:212`); tests pass `--anki-url` (A7: real URL `http://127.0.0.1:8765` is the default).
- The homepage stamp keeps saying `rigenera con <code>npm run home</code>` and the help keeps the
  `npm run home` lines: changing them is a content change that A12 forbids before cutover; the docs issue owns
  the switch (D11).
- Curriculum round-trip uses `serde_json::Map` (crate `serde_json` 1.x with `preserve_order`, already
  enabled), never typed structs: unknown chapter keys and key order survive a `plan` of another chapter
  (A2 "JSON keys in insertion order"; `chapter.ts:69-72`). A re-planned chapter is rebuilt as
  `{title, slug, lessons}` and each planned lesson as `{title, slug[, plannedNodes]}`, like Node. The file is
  `serde_json::to_string_pretty(&{"chapters": [...]}) + "\n"` (2-space indent, same as `JSON.stringify(_, null, 2)`);
  top-level keys other than `chapters` are dropped, as Node does.
- Sorting: course directories and file names by UTF-16 code units (`readdirSync().sort()`); the final
  `localeCompare` sort by course is replaced by the same code-unit order (stable sort, then `lesson_number`).
  Identical for slug directory names (lowercase ASCII, digits, `-`), which is what the engine creates; mixed-case,
  `_` or accented directory names may order differently — documented in a doc comment on `scan_lessons`.
- `fetchAnkiStatus` is ported whole, `byCourse` included: D10 moves its tests here, and its `courseSlugs` scan
  is observable (a corrupt lesson's `Ignorata ...` warning is printed twice when Anki is online). `anki.rs`
  takes the course-slug list and the deck-name function as closures, so it depends on no other new module;
  `homepage.rs` supplies `course_slugs` / `course_deck_name_for` (the latter reads `<baseDir>/curriculum.json`,
  ignoring `--curriculum`, exactly like `anki-sync.ts:199-208`).
- `fetchDeckStatus` is **not** ported (only the server's `/api/anki` uses it, issue #8); its three TS tests stay
  in `tests/homepage.test.ts`, everything else in that file is deleted (D10).
- HTTP: `reqwest` 0.13.5 (installed; `Cargo.lock`) moves from dev-dependency to dependency with
  `default-features = false` (no TLS, no `system-proxy` → like Node `fetch`, which ignores `HTTP_PROXY`). Async API
  from the installed source: `Client::new()`, `client.post(url).header(..).body(Vec<u8>).timeout(Duration)
  .send().await`, `Response::status()`, `Response::bytes().await`, `Error::is_timeout()`,
  `Error::is_builder()`. The CLI drives it with a `tokio` (1.54.1, installed) current-thread runtime. No new crate.
- Unicode NFD for `slugify`: `icu_normalizer` 2.4.0 (already in `Cargo.lock` via `url`/`idna`), as a direct
  dependency with `default-features = false, features = ["compiled_data"]` (its `utf8_iter`/`utf16_iter`
  defaults would pull crates absent from the lock). API from the installed source:
  `icu_normalizer::DecomposingNormalizerBorrowed::new_nfd().normalize(&str) -> Cow<str>`.
- Local time for the it-IT stamp without a new crate: `libc` 0.2.191 (`localtime_r`, in the lock) on
  `cfg(unix)`, `windows-sys` 0.61.2 (`SystemTimeToTzSpecificLocalTime`, features `Win32_Foundation`,
  `Win32_System_Time`, in the lock) on `cfg(windows)`; UTC fallback elsewhere/on failure. Format
  `dd/mm/yyyy, HH:MM:SS`, zero-padded (verified: Node 26 `new Date(2026,0,3,9,5,7).toLocaleString("it-IT")` →
  `03/01/2026, 09:05:07`).
- `slugify` = JS steps on JS semantics: `to_lowercase`, trim JS whitespace, `&`→`and`, NFD, then keep only
  ASCII `[A-Za-z0-9_]`, `-` and JS `\s` (the `\p{Diacritic}` strip is subsumed by this filter: the filter has no
  `u` flag, so every non-ASCII non-space char is dropped anyway), collapse runs of `\s`/`_`/`-` to `-`, trim
  `-`. JS `\s` = `\t \n \u{B} \u{C} \r \u{20} \u{A0} \u{1680} \u{2000}-\u{200A} \u{2028} \u{2029} \u{202F}
  \u{205F} \u{3000} \u{FEFF}`.
- `toFixed(1)` is round-half-up on the exact binary value, Rust `{:.1}` is half-even (6.25 → JS `6.3`, Rust
  `6.2`, reachable with 1 of 16 lessons taught): `to_fixed_1` formats `{:.60}` (exact for 0..=100) and rounds
  the decimal string half-up by hand.
- `parseArgs` replica (strict, `allowPositionals`), messages verified on Node 26.5.0:
  - `Option '--chapter <value>' argument missing`
  - `Option '--chapter' argument is ambiguous.\nDid you forget to specify the option argument for '--chapter'?\nTo specify an option argument starting with a dash use '--chapter=-XYZ'.`
  - `Option '--no-anki' does not take an argument`; for help: `Option '-h, --help' does not take an argument`
  - `Unknown option '<name>'. To specify a positional argument starting with a '-', place it at the end of the command after '--', as in '-- "<name>"` (no closing quote; reuse `data_root::unknown_option` text).
- Paths: `--dir/--curriculum/--out` resolve against the data root via a new
  `data_root::resolve_path_from(base, p)` (Node `path.resolve` without touching the filesystem); `resolve_path`
  becomes `resolve_path_from(current_dir, p)`. Hrefs are built with `/` on every OS.
- Empty-string option values are JS-falsy: `--dir=`, `--curriculum=`, `--out=`, `--anki-url=`, `--slug=` mean
  "not given"; `--chapter=` and `--lessons-json=` trigger the "plan requires ..." errors.

**Known deviations (malformed input only, never produced by the engine; documented in doc comments):** V8
`JSON.parse`/`TypeError` texts (invalid `--lessons-json`, invalid `curriculum.json`, an AnkiConnect body that is
not JSON) are replaced by serde/io messages with the same `Error: ` prefix and exit 1; a lesson island without
`metadata`/`nodes`, a non-object island, a non-string `title`/`slug` in `--lessons-json`, non-object chapters,
non-integer `lessonNumber`/Anki counts and float literals like `4.0` are read leniently (missing → `""`/`0`/empty)
where Node would crash or print `undefined`; an I/O error on `--out` prints the Rust io message.

**Rejected.** Typed serde structs for the curriculum (drop unknown keys, A2). Live Node-vs-binary parity like
`data_cli.rs` (dies with the TypeScript, A12). `chrono`/`unicode-normalization` (not in the lock; equivalents
already are). Raw golden files in a `home/` directory (CRLF checkouts break byte comparison). Reading
`LEARNER_ANKI_URL` in `home` (superset of Node, breaks D11). Porting `fetchDeckStatus` now (unused by `home`).
Sorting with an ICU collator (not installed; slug names sort identically).
