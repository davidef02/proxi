# Learned rules

- When editing an existing file for a task: change only the lines the task needs; leave unrelated formatting, comments and banners byte-identical to the base branch.
- When porting parsing or scanning code from Node to Rust, copy the original's failure boundary and pin it with a malformed-input test (a port that drops the error diverges silently on malformed input).
- When a request handler checks shared state and then acts on it, even after an await: do the check, the decision and the write under the same lock (a lock released between them lets two concurrent requests both pass and duplicate the work).
- When building JSON in Rust that must match Node's key order: build a fresh map in the Node order, emit array-index keys (`"0"`–`"4294967294"`) first in ascending numeric order, and assert the serialised string (V8 enumerates array-index keys before string keys; `Map::remove`/`insert` reorder too).
- When several Rust integration-test binaries need the same seed or golden helpers, define them once in `crates/proxi/tests/common/` and call them from each test file (per-binary copies drift silently, so editing one leaves the others untested).
- When porting Node code into a new Rust module and the crate already has the same helper (e.g. `esc`): make the existing one `pub(crate)` and call it, never copy the function (a byte-identical copy drifts from the original and review sends the change back).
- When hand-porting a JS regex or scan to Rust: mirror the reference traversal exactly (one alternation pass with the earliest match winning, retry at `start + 1`, a stripped line keeps its newline) and test the exact Node output (two-pass stripping, dropped newlines and a `start + 3` skip each diverged and cost a fix round).
- When bounding a blocking pass in Tokio: stop it cooperatively or shut the runtime down with `shutdown_timeout`/`shutdown_background` (`timeout` around `spawn_blocking` leaves the task running and dropping the runtime waits for it, so quitting hangs for minutes).
- When a test needs an external prerequisite or polls for an asynchronous condition: assert the condition or panic on failure or timeout, never exit or skip silently (a test that exits without checking goes green falsely).
- When a second ported module needs a helper the crate already has: make the existing one `pub(crate)` and call it there, never paste a copy into the module (byte-identical copies drift and cost a fix round).
- When a test removes a temp folder on Windows after killing a server: use a bounded retry helper instead of rmSync (the killed engine child holds the folder past its ~475 ms budget and teardown failed with EPERM).
